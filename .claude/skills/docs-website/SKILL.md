> House skill — established by dz-runner setup mode from this repo's own evidence, then owned by its maintainers. Correct it in place; setup never overwrites a skill that exists.

1. Documentation pages live under `docs/eng/<section>/<page>.md`; the site config is `docs/.vitepress/config.js`.
2. Add a page to the sidebar in `docs/.vitepress/config.js` when you create a new file, otherwise it is unreachable from the nav.
3. Write pages in Markdown with VitePress frontmatter; use fenced code blocks with a language tag.
4. Run `bun run docs:dev` from apps/bun-on-rails to preview locally at the VitePress dev URL. Stop it with Ctrl+C — do not leave the watcher running.
5. Build the site with `bun run docs:build` from apps/bun-on-rails. Fail -> fix the broken markdown; the output lands in `docs/.vitepress/dist`.
6. Preview the built site with `bun run docs:preview` from apps/bun-on-rails.
7. `docs/.vitepress/config.js` sets `ignoreDeadLinks: true` — dead links do not fail the build, so check links manually.
8. CI (`.github/workflows/docs.yml`) rebuilds and deploys to GitHub Pages on any push touching `docs/**`; the `ci.yml` build job also runs `bun run docs:build`. The deploy workflow additionally requires a repository setting that the workflow cannot grant itself: **GitHub Pages must be provisioned for this repository with Settings > Pages > Build and deployment > Source = "GitHub Actions"**. When it is missing, the `Preflight Pages site` step (a non-fatal read of the repository's Pages site) reports that required setting as a warning — it never blocks the run, so the following `Setup Pages` step still runs — and that step (`actions/configure-pages`, pinned to `v6.0.0`), running with `enablement: true`, enables/provisions the site instead of only looking it up (previously it failed at `Setup Pages` with a bare Pages-site lookup 404 — see run 41669345427); note that `enablement` alone cannot express "configure if present" (it is true/false only), that *creating* the site needs a token the API allows to create Pages sites (the action asks for a token other than the default `GITHUB_TOKEN` — a PAT with `repo` scope or Pages write permission, or a GitHub App with `administration:write`), and that org policy can still deny the workflow token permission to create Pages sites — the preflight exists so that failure mode stays legible, and the setting must be provisioned in the repository if the token is denied. The failing run 41669345427 (https://github.com/developerz-ai/bun-on-rails/actions/runs/41669345427) was _triggered_ by the docs merge 23ee9d66fa3e498bb7191b2ebe962709e44ad02d (PR #22, reviewed with 0 findings), which merely matched the workflow's `paths: ['docs/**']` filter; it was not _caused_ by that merge, and the preceding `Build documentation` step (`bun run docs:build`) passed in that run.
